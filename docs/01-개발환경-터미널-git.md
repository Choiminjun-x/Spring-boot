# 1회차 — 개발환경 · 터미널 · Git

## 서버란 무엇인가?

- 서버는 특별한 하드웨어가 아니라 프로그램
- 포트를 점유하고 요청을 기다리는 프로세스

### 클라이언트-서버

- 말은 항상 클라이언트가 먼저 건다.
- 요청 하나하나는 원칙적으로 독립적이다
- 서버는 여러 클라이언트를 동시에 상대한다

## 요청이 어떻게 내 코드까지 찾아오는가?

### IP 주소

- "지구상의 어느 컴퓨터냐"를 결정
- `localhost`, `127.0.0.1` — 이 컴퓨터 자신을 지칭

### 포트 번호

- "그 컴퓨터의 어느 프로그램이냐"를 결정, 0~65535까지 있음
- 0~1023: well-known port로 용도가 관례적으로 정해짐
  - 80: HTTP
  - 443: HTTPS
  - 22: SSH
- 3306: MySQL

### 기억할 규칙 — 하나의 포트는 한 프로세스만 점유할 수 있음

- 에러 메시지 `Port 8080 was already in use`
- 에러 발생은 나중에 실행한 쪽
- 해법은 점유 중인 프로세스를 찾아 죽이기 &gt; kill option(9, 15)

### "서버를 띄운다"의 의미

- 어떤 프로세스가 특정 포트를 점유(bind)하고, 그 포트로 들어오는 연결을 기다리는(listen) 상태가 되는 것 &gt; 떠있는 서버를 어떻게 하면 특정지을 수 있을지 ? netstat -ntlp 

### `http://localhost:8080/health`

- **IP, 포트** — 어느 컴퓨터의 어느 프로그램인지를 결정, 읽는 주체는 OS/네트워크
- **경로(`/health`)** — 한 프로그램 안에서 어떤 기능을 부를지 고르는 문자열, 읽는 주체는 서버 프로그램

&lt; /etc/hosts 

## JVM은 무엇이고 왜 필요한가?

### 컴파일 방식

- 실행 전에 소스코드 전체를 기계어로 번역해두고, 나중에 그 번역 결과물을 실행
- 번역이 미리 끝나 있어 실행이 빠름
- 번역 결과물이 특정 CPU, 특정 OS 전용 → 맥에서 컴파일한 실행 파일은 리눅스 서버에서 작동되지 않음

### 인터프리터 방식

- 미리 번역하지 않고, 실행 시점에 한 줄씩 읽어가며 그때그때 해석
- 실행 환경마다 인터프리터만 깔려 있으면 같은 소스가 어디서든 실행 가능
- 매번 해석하는 비용이 있어서 느리다

### 자바의 해법 — 중간 단계를 하나 만드는 것

```
Main.java  --(javac 컴파일)-->  Main.class  --(JVM이 실행)-->  동작
   소스                          바이트코드
```

- `.class` 파일에 든 바이트코드 — JVM이라는 가상의 컴퓨터를 위한 명령어, 실제 CPU는 이것을 읽지 못한다
- 읽어서 진짜 기계어로 바꿔 실행해주는 게 JVM의 일
- 바이트코드는 어디서나 같고, JVM은 OS마다 다름, OS 차이는 JVM이 흡수
- 자바는 컴파일 후 인터프리트 구조
- "Write Once, Run Anywhere"

### JVM

- 바이트코드를 실행하는 실행기
- **실행** — 바이트코드를 기계어로 바꿔 돌린다. 자주 실행되는 부분은 아예 기계어로 캐싱해두는 JIT 컴파일이라는 최적화가 있음
- **메모리 관리** — 객체를 어디에 놓을지 정하고, 안 쓰는 객체를 알아서 치운다. 이것이 GC &lt;&lt; 메모리 구조 공부, gc 종류
- **격리** — 코드가 OS를 직접 건드리지 못하게 막는다

### JVM / JRE / JDK

- **JRE** = JVM + 실행에 필요한 기본 라이브러리
- **JDK** = JRE + `javac` 같은 개발 도구

### `java -jar`

- `.jar` — `.class` + 리소스를 zip으로 묶은 것, 진입점은 `MANIFEST.MF`에 기록
- `java -jar app.jar` — JVM을 켜서 이 바이트코드 뭉치를 실행하라
- JDK/JRE 미설치 시 `bash: java: command not found` → 애플리케이션 에러가 아닌 서버 환경 문제

## 터미널 — 왜 필요한가?

- 터미널은 서버 환경에서의 유일한 인터페이스
- 터미널은 항상 현재 디렉토리 기준으로 동작

### 명령어


| 명령어      | 하는 일     | 옵션                                        |
| -------- | -------- | ----------------------------------------- |
| `pwd`    | 지금 위치 출력 | print working directory                   |
| `ls -al` | 파일 목록    | `-a` 숨김 파일 포함, `-l` 상세(권한, 소유자, 크기, 수정시각) |
| `cd`     | 위치 이동    | `cd ..` 상위로, `cd ~` 홈으로, `cd -` 직전 위치로    |
| `mkdir`  | 디렉토리 생성  |                                           |
| `rm`     | 삭제       | `-r` 디렉토리째, `-f` 확인 없이                    |


- 유닉스에서 이름이 `.`으로 시작하면 숨김 파일, `-a` 없이는 아예 안 보인다

### 경로 표기

- `/`로 시작하면 절대경로(루트부터의 전체 주소), 아니면 상대경로(현재 위치 기준)
- `.`은 현재 디렉토리, `..`은 상위 디렉토리

## Git — 왜 필요한가?

### Git

- 파일의 변경 이력을 저장하는 도구
- 과거의 어느 시점으로든 되돌아갈 수 있음
- 여러 사람이 같은 코드를 동시에 고쳐도 충돌을 관리할 수 있음

### 공간

```
Working Directory --(git add)--> Staging Area --(git commit)--> Repository --(git push)--> Remote
```

- **Working Directory** — 지금 편집 중인 실제 파일들
- **Staging Area** — 커밋에 담을 것을 골라내기 위한 공간
- **Repository** — 커밋이 쌓이는 이력 저장소

### `.gitignore` — git 추적 대상에서 제외

- 빌드 산출물(`build/`, `*.jar`)
- IDE 설정(`.idea/`)
- 비밀값(DB 비밀번호, API 키)
